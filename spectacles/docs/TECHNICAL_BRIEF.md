# Spectral: one optical model, two interaction runtimes

**Purpose.** Make an abstract optics lesson something learners can hold and investigate together. A teacher asks which colour bends most, learners make a prediction, then move the glass and compare that prediction with the computed path. The intended benefit is shared spatial understanding, not a promise of photorealistic virtual lighting.

**Mathematics.** A convex solid is the intersection of half-spaces `n·x ≤ h`. Ray/plane intervals identify entry and exit faces; the render mesh is built from those same planes. Each of 31 wavelengths from 420–680 nm follows Snell refraction, unpolarized Fresnel transmission and total internal reflection. Work stops after five internal encounters; unresolved paths produce no false exit. Labels read the actual interface events. Crown glass, diamond, water and ordinary-ray sapphire use sourced Sellmeier curves; the frozen iPhone version uses its existing Cauchy glass model. Sapphire birefringence, polarization transport, fluid boundaries, absorption and reflected branch splitting are outside this version.

**Two runtimes.** iPhone uses ARKit, touch/Vision interactions, camera/depth textures and a custom Metal renderer. The Lens build consumes SIK-managed transforms and expresses the lesson in TypeScript, with direct/indirect hand interaction, a Spectacles ASR adapter and a Code Node crystal material that performs per-fragment spectral transport through the same convex boundary. Both expose Soft, Spot, Strip, Window and Halo light profiles and let the user move the optical solid and source independently in 3D. This is **shared model/geometry and separate implementations**, not one binary engine running unchanged. The Lens material uses camera reprojection and far-field sampling; it does not reproduce the iPhone renderer's guided depth ray march or Metal caustic passes. The rays remain an instructional overlay and the Lens receiver is a bounded room-query approximation.

**Room and collaboration.** The Lens adapter queries a real surface at at most 5 Hz, fits a bounded local receiver plane, and rejects callbacks from older poses. The native World Mesh depth-occlusion path is configured: a WorldMesh_Occlusion visual renders the real mesh with depth write only, hiding virtual geometry behind room surfaces. Dynamic environment lighting from the device camera is enabled on the Envmap LightSource (`UseEnvMapFromCamera: true`, `DynamicEnvInputTexture` set); the baked Echopark.hdr remains as fallback. Both require Spectacles device validation. SIK manipulation and Sync Kit settings provide the integration path to a colocated lesson. Transform state and discrete light/material controls are separate; no room images or speech transcripts are stored by our code. Two-device synchronization remains untested.

**Performance and evidence.** Every aperture sample carries a normalized energy weight and every sample traces 31 wavelengths. Depending on the selected rig, an optical rebuild evaluates 31–248 bounded paths. One 256×1 colour texture and two batched meshes avoid per-ray objects and a full-screen spectral shader. Optical work is capped at 20 Hz while transforms change and sleeps when state is stable; the display and hand tracking continue at the Lens frame rate. The in-world panel measures display FPS, optical CPU p50/p95, optical update rate, path count, generated vertices and receiver-query rate. Host tests cover material reference values, reversibility, Fresnel limits, geometry closure, light-energy conservation, dispersion, finite termination and stale-query rejection. Host results establish numerical behavior and comparative CPU cost, not wearable thermal or GPU performance.

**Product hypothesis.** Validate with physics teachers: can two learners correctly explain normal-relative angles and TIR after a short shared exercise, and can a teacher start it without developer help? Compare against a conventional diagram lesson. Measure setup time, prediction accuracy, retention and voluntary reuse before calling it a useful teaching product.

**Status:** iPhone preserved; Lens project opens and runs in Lens Studio, with the current update passing host tests and the editor declaration check. Latest-edit visual review, Spectacles hardware capture, two-device validation and publication still remain. No public release or usage claims.
